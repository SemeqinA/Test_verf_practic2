## Как повторить запуск в VS Code

Открой терминал PowerShell в папке проекта, где находятся `main.py` и
`requirements-dev.txt`. Один раз создай отдельное окружение и установи зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

Запуск всех тестов:

```powershell
.\.venv\Scripts\python.exe -m pytest -v
```

Ожидаемый итог исправленной версии: `26 passed`.

Запуск с измерением покрытия:

```powershell
.\.venv\Scripts\python.exe -m pytest --cov=file_operations --cov-branch --cov-report=term-missing --cov-report=html:htmlcov
```

После этого открой `htmlcov/index.html` в браузере. Файл
`results/coverage_html/index.html` уже содержит отчёт сохранённого запуска.

Активация окружения не требуется: команды обращаются прямо к его Python.
Если `python` не находится при создании окружения, используй `py -m venv .venv`.
Техническая проверка ассистента выполнялась в отдельном окружении вне проекта;
его не нужно переносить вместе с проектом.

## Какие сценарии проверяются

| Функция | Случаев | Основные проверки |
|---|---:|---|
| Чтение | 4 | Русский текст, пустой файл, отсутствие файла, неверная кодировка |
| Запись | 5 | Создание, пустой текст, полная перезапись, отсутствие папки |
| Добавление | 4 | Сохранение старого текста, отсутствие лишнего переноса, пустое добавление, создание |
| Копирование | 5 | Двоичные данные, пустой файл, замена назначения, отсутствующий источник, копирование в себя |
| Поиск | 8 | Номера строк, регистр, отсутствие совпадений, пустой файл и запрос, отсутствующий файл, пробелы и повторы, последняя строка без переноса |

Функций с именем `test_...` в коде меньше 26: декоратор
`@pytest.mark.parametrize` запускает некоторые из них несколько раз с разными данными.

Каждый тест использует свою временную папку `tmp_path`, поэтому он не зависит
от `example.txt` и не меняет пользовательские файлы. Данные создаются через
`pathlib`, а не другими функциями проверяемого модуля: ошибка записи не должна
маскироваться такой же ошибкой чтения.

## Разбор теста, обнаружившего дефект

```python
def test_search_line_numbers_start_at_one(tmp_path):
    path = tmp_path / "text.txt"
    path.write_text("Python\nJava\nPython снова\n", encoding="utf-8")
    result = search_in_file(str(path), "Python")
    assert result == [(1, "Python"), (3, "Python снова")]
```

1. **Подготовка:** создаём файл с известным содержимым.
2. **Действие:** вызываем функцию поиска.
3. **Проверка:** `assert` сравнивает результат с ожидаемым списком.

В исходной версии функция возвращала номера `0` и `2`, поэтому сравнение
проваливалось и pytest отмечал тест словом `FAILED`. После добавления `start=1`
возвращаются номера `1` и `3`, и тест получает статус `PASSED`.

`pytest.raises(FileNotFoundError)` проверяет другой вид результата: функция
должна выдать конкретное исключение. Такой тест проходит, если исключение
возникло ожидаемым образом.

## Как повторно увидеть исходную ошибку

Команда ниже добавляет `before_fix` в начало пути импорта только для этого запуска.
Рабочий исправленный модуль остаётся на месте:

```powershell
.\.venv\Scripts\python.exe -m pytest -v -o pythonpath=before_fix
```

Ожидаемый итог: `4 failed, 22 passed`. Для обычного успешного запуска убери
`-o pythonpath=before_fix`.
