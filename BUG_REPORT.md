# Дефект FILE-001: неправильные номера строк в результатах поиска

Дата проверки: 07.10.2026.

- Компонент: `search_in_file` в `file_operations.py`.
- Серьёзность: Minor (незначительная). Строки находятся правильно, но их номера неверны.
- Начальный статус: Open.
- Итоговый статус: Closed после исправления и успешной повторной проверки.
- Окружение: Windows, Python 3.13.7, pytest 9.1.1, pytest-cov 7.1.0.
- Обнаруживающий тест: `test_search_line_numbers_start_at_one`.

## Воспроизведение на исходной версии

1. Создать текстовый файл UTF-8 с содержимым:

   ```text
   Python
   Java
   Python снова
   ```

2. Вызвать `search_in_file` с путём к файлу и запросом `Python`.
3. Сравнить номера найденных строк с номерами строк в файле.

Ожидаемый результат: `[(1, "Python"), (3, "Python снова")]`.

Фактический результат: `[(0, "Python"), (2, "Python снова")]`.

## Причина и исправление

Счётчик `enumerate(file)` по умолчанию начинается с нуля, а документация
требует нумерацию с единицы. Исправлена одна строка:

```diff
-        for line_number, line in enumerate(file):
+        for line_number, line in enumerate(file, start=1):
```
